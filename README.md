# 🏠 StayFlow Backend

A production-grade Airbnb clone REST API built with Node.js, TypeScript, Express, PostgreSQL, and Prisma.

---

## 🧰 Tech Stack

| Layer            | Technology                    |
| ---------------- | ----------------------------- |
| Runtime          | Node.js v20+                  |
| Language         | TypeScript 5                  |
| Framework        | Express.js                    |
| ORM              | Prisma 7                      |
| Database         | PostgreSQL 15                 |
| Cache            | Redis 7                       |
| Auth             | JWT (Access + Refresh Tokens) |
| Validation       | Zod v4                        |
| Payment          | Razorpay                      |
| File Upload      | Cloudinary / AWS S3           |
| Logging          | Winston                       |
| API Docs         | Swagger (OpenAPI 3.0)         |
| Containerization | Docker + Docker Compose       |

## 🗄️ Database Schema

```
User              → id, name, email, passwordHash, role (GUEST/HOST/ADMIN)
Property          → id, hostId, title, pricePerNight, city, country, lat, lng
PropertyImage     → id, propertyId, url, isPrimary
Amenity           → id, name, icon
PropertyAmenity   → propertyId, amenityId (many-to-many)
Booking           → id, propertyId, guestId, checkIn, checkOut, totalPrice, status
Payment           → id, bookingId, amount, gatewayOrderId, status
Review            → id, propertyId, guestId, bookingId, rating, comment
Wishlist          → id, userId, propertyId
```

## ⚙️ Request Flow

```
Request
  → Route            (URL to controller mapping)
  → Middleware        (auth guard, Zod validation)
  → Controller        (req/res handling only)
  → Service           (all business logic)
  → Repository        (all DB queries)
  → Prisma → PostgreSQL
```

## 🚀 Getting Started

### Prerequisites

- Node.js v20+
- Docker + Docker Compose
- npm

### 1. Clone and install

```bash
git clone https://github.com/yourusername/stayflow-backend.git
cd stayflow-backend
npm install
```

### 2. Environment setup

```bash
cp .env.example .env
```

Fill in your `.env`:

```env
NODE_ENV=development
PORT=5000
APP_NAME=StayFlow
CLIENT_URL=http://localhost:3000

DATABASE_URL="postgresql://stayflow_user:stayflow_password@localhost:5432/stayflow_db"
REDIS_URL="redis://localhost:6379"

JWT_ACCESS_SECRET=your_access_secret_here
JWT_REFRESH_SECRET=your_refresh_secret_here
JWT_ACCESS_EXPIRES_IN=15m
JWT_REFRESH_EXPIRES_IN=7d
```

### 3. Start database containers

```bash
docker compose up -d
```

### 4. Run migrations

```bash
npx prisma migrate dev --name init
```

### 5. Start development server

```bash
npm run dev
```

Server runs at `http://localhost:5000`

### 6. Health check

```bash
curl http://localhost:5000/api/health
```

## 🔐 Authentication

StayFlow uses a **dual token strategy**:

| Token         | Type | Expiry     | Storage         |
| ------------- | ---- | ---------- | --------------- |
| Access Token  | JWT  | 15 minutes | Response body   |
| Refresh Token | JWT  | 7 days     | httpOnly Cookie |

**Protected routes** require `Authorization: Bearer <accessToken>` header.

**Role-based access:**

- `GUEST` — search properties, make bookings, write reviews
- `HOST` — all guest permissions + create/manage properties
- `ADMIN` — full access

## 🧱 SOLID Principles Applied

| Principle                 | How                                                                                      |
| ------------------------- | ---------------------------------------------------------------------------------------- |
| **Single Responsibility** | Controller handles req/res only. Service handles logic only. Repository handles DB only. |
| **Open/Closed**           | New features = new modules. Existing code untouched.                                     |
| **Liskov Substitution**   | Repositories implement interfaces — swappable for testing.                               |
| **Interface Segregation** | Each module has its own interface — no fat interfaces.                                   |
| **Dependency Inversion**  | Services depend on repository interfaces, not concrete classes.                          |
